# Requirements Document

## Introduction

MVP-интерфейс для Dither Engine — минимальный фронтенд, позволяющий пользователю загрузить фотографию, применить фильтры дизеринга/обработки и увидеть результат в реальном времени. Интеграция с существующим Rust-движком через Tauri IPC. Цель — связать воедино engine-tiles, engine-project (документ, слои, фильтры) и отобразить результат обработки на экране.

## Glossary

- **Frontend**: React/TypeScript приложение в директории `frontend/`, работающее внутри Tauri WebView
- **Engine**: Rust backend, состоящий из crates engine-core, engine-tiles, engine-project
- **Tauri_IPC**: Механизм вызова Rust-команд из JavaScript через `@tauri-apps/api/core` invoke
- **Document**: Структура данных документа в engine-project (размеры, слои, фильтры)
- **DocumentId**: Уникальный идентификатор документа, возвращаемый при загрузке изображения
- **Layer**: Слой в документе (raster или adjustment) с набором фильтров
- **Filter**: Алгоритм обработки пикселей (Curves, Levels, Dither, Glitch)
- **PixelTile**: Блок 256×256 пикселей + halo, базовая единица рендеринга в engine-tiles
- **TileCache**: Кэш для хранения отрендеренных тайлов
- **Preview_Canvas**: HTML Canvas элемент для отображения обработанного изображения
- **File_Dialog**: Нативный системный диалог выбора файлов через Tauri API
- **Rendered_Image**: Результат применения фильтров к загруженному изображению в формате RGBA
- **MipLevel**: Уровень пирамиды тайлов для масштабированного отображения

## Requirements

### Requirement 1: Загрузка изображения

**User Story:** As a пользователь, I want to загрузить фотографию с диска, so that я могу применить к ней фильтры обработки.

#### Acceptance Criteria

1. WHEN пользователь нажимает кнопку «Открыть файл», THE Frontend SHALL открыть нативный File_Dialog для выбора изображения
2. THE File_Dialog SHALL ограничивать выбор форматами PNG, JPEG и WebP
3. WHEN файл выбран через File_Dialog, THE Engine SHALL загрузить изображение по указанному пути в память и создать Document с шириной и высотой равными размерам изображения в пикселях
4. WHEN изображение успешно загружено, THE Frontend SHALL отобразить его на Preview_Canvas без применения фильтров
5. IF путь к файлу недоступен или формат не поддерживается, THEN THE Frontend SHALL отобразить сообщение об ошибке с указанием причины (файл не найден или неподдерживаемый формат)
6. THE Engine SHALL поддерживать изображения размером от 1×1 до 8192×8192 пикселей
7. IF выбранное изображение превышает 8192×8192 пикселей по любому измерению, THEN THE Engine SHALL вернуть ошибку, и THE Frontend SHALL отобразить сообщение об ошибке с указанием допустимого максимального размера
8. IF пользователь закрывает File_Dialog без выбора файла, THEN THE Frontend SHALL сохранить текущее состояние без изменений

### Requirement 2: Отображение превью изображения

**User Story:** As a пользователь, I want to видеть загруженное и обработанное изображение в реальном времени, so that я могу оценить результат применения фильтров.

#### Acceptance Criteria

1. THE Frontend SHALL отображать изображение на Preview_Canvas, масштабируя его для вмещения в видимую область центральной зоны (fit-to-view) с сохранением пропорций (aspect ratio) исходного изображения
2. WHEN размеры окна изменяются, THE Frontend SHALL пересчитать масштаб Preview_Canvas с сохранением aspect ratio в течение 200 мс после окончания изменения размеров (debounce)
3. THE Engine SHALL рендерить изображение через tile pipeline и возвращать RGBA-данные для отображения на Preview_Canvas
4. WHEN фильтры применены к слою, THE Frontend SHALL обновить Preview_Canvas с результатом обработки в течение 500 мс после завершения рендеринга
5. WHILE изображение рендерится, THE Frontend SHALL отображать визуальный индикатор загрузки поверх Preview_Canvas, не скрывая предыдущее состояние изображения
6. IF рендеринг завершился с ошибкой, THEN THE Frontend SHALL отобразить сообщение об ошибке и сохранить последнее успешно отрендеренное изображение на Preview_Canvas

### Requirement 3: Применение фильтров

**User Story:** As a пользователь, I want to применять фильтры дизеринга и обработки к загруженному изображению, so that я могу получить художественный результат.

#### Acceptance Criteria

1. THE Frontend SHALL отображать панель с доступными фильтрами: Dither, Curves, Levels, Glitch
2. WHEN пользователь выбирает фильтр из панели, THE Frontend SHALL добавить его в конец списка фильтров текущего слоя через Tauri_IPC вызов add_filter
3. WHEN фильтр добавлен к слою, THE Engine SHALL применить все фильтры слоя в порядке их добавления к PixelTile данным изображения и вернуть обновлённый Rendered_Image
4. THE Frontend SHALL отображать параметры последнего выбранного (активного) фильтра в боковой панели
5. WHEN пользователь изменяет параметр фильтра, THE Frontend SHALL отправить обновлённые параметры в Engine через Tauri_IPC и обновить Preview_Canvas после получения результата
6. THE Frontend SHALL позволять удалить добавленный фильтр из слоя через кнопку удаления рядом с названием фильтра в списке
7. IF добавление или удаление фильтра завершается ошибкой Engine, THEN THE Frontend SHALL отобразить сообщение об ошибке и сохранить предыдущее состояние фильтров

### Requirement 4: Параметры фильтра Dither

**User Story:** As a пользователь, I want to настраивать параметры дизеринга, so that я могу контролировать стиль и интенсивность эффекта.

#### Acceptance Criteria

1. THE Frontend SHALL предоставлять выбор алгоритма дизеринга из списка: Floyd-Steinberg, Ordered (Bayer), Threshold, с алгоритмом Floyd-Steinberg выбранным по умолчанию
2. THE Frontend SHALL предоставлять ползунок color_depth с целочисленными значениями от 1 до 8 бит на канал, с шагом 1 и значением по умолчанию 4
3. WHEN пользователь изменяет алгоритм или color_depth, THE Engine SHALL пересчитать отображаемое изображение с новыми параметрами дизеринга
4. THE Frontend SHALL отображать текущее числовое значение color_depth в битах рядом с ползунком
5. IF Engine не может завершить пересчёт изображения после изменения параметров дизеринга, THEN THE Frontend SHALL отобразить сообщение об ошибке с указанием причины сбоя и сохранить последнее успешно отрендеренное изображение
6. IF пользователь задаёт значение color_depth вне диапазона 1–8, THEN THE Frontend SHALL отклонить ввод и сохранить последнее допустимое значение

### Requirement 5: Параметры фильтров Curves и Levels

**User Story:** As a пользователь, I want to настраивать тональные кривые и уровни, so that я могу корректировать яркость и контраст изображения.

#### Acceptance Criteria

1. WHEN фильтр Curves активен, THE Frontend SHALL отображать редактор кривой с контрольными точками (input, output) в диапазоне 0.0–1.0 и выбором канала (Red, Green, Blue, All, Luminance), с каналом All выбранным по умолчанию
2. WHEN фильтр Levels активен, THE Frontend SHALL отображать ползунки input_black (0.0–1.0, по умолчанию 0.0), input_white (0.0–1.0, по умолчанию 1.0), gamma (0.1–10.0, по умолчанию 1.0), output_black (0.0–1.0, по умолчанию 0.0), output_white (0.0–1.0, по умолчанию 1.0)
3. WHEN пользователь изменяет значение ползунка или контрольную точку кривой, THE Frontend SHALL отправить обновлённые параметры в Engine в течение 100 мс (debounce)
4. THE Frontend SHALL отображать числовые значения параметров с точностью до 2 знаков после запятой рядом с ползунками
5. IF Engine возвращает ошибку при обновлении параметров Curves или Levels, THEN THE Frontend SHALL отобразить сообщение об ошибке и откатить UI к предыдущим валидным значениям

### Requirement 6: Параметры фильтра Glitch

**User Story:** As a пользователь, I want to настраивать glitch-эффекты, so that я могу добиться нужного уровня "сломанности" изображения.

#### Acceptance Criteria

1. WHEN фильтр Glitch активирован впервые, THE Frontend SHALL отображать ползунок intensity с диапазоном 0.0–1.0, шагом 0.01 и начальным значением 0.5
2. WHEN фильтр Glitch активен, THE Frontend SHALL предоставлять выбор типа эффекта из вариантов: RGB Shift (по умолчанию) и Block Displacement
3. WHEN пользователь изменяет intensity или тип эффекта, THE Engine SHALL пересчитать Rendered_Image с новыми параметрами и обновить отображение
4. THE Frontend SHALL отображать текущее числовое значение intensity с точностью до 2 знаков после запятой рядом с ползунком
5. IF Engine возвращает ошибку при применении параметров Glitch, THEN THE Frontend SHALL отобразить сообщение об ошибке с указанием причины и сохранить предыдущие валидные параметры фильтра
6. WHEN значение intensity равно 0.0, THE Engine SHALL вернуть изображение без изменений (no-op)

### Requirement 7: Экспорт результата

**User Story:** As a пользователь, I want to сохранить обработанное изображение на диск, so that я могу использовать его в других приложениях.

#### Acceptance Criteria

1. WHEN пользователь нажимает кнопку «Сохранить», THE Frontend SHALL открыть нативный File_Dialog для выбора пути сохранения
2. THE File_Dialog SHALL предлагать форматы сохранения: PNG и JPEG
3. WHEN путь выбран, THE Engine SHALL закодировать полноразмерный Rendered_Image в выбранный формат (JPEG — с quality 90) и записать файл на диск
4. WHEN файл успешно сохранён, THE Frontend SHALL отобразить уведомление с подтверждением сохранения, содержащее имя файла, которое автоматически скрывается через 5 секунд
5. IF запись файла не удалась, THEN THE Frontend SHALL отобразить сообщение об ошибке с описанием причины, полученной от Engine
6. IF пользователь отменяет File_Dialog без выбора пути, THEN THE Frontend SHALL закрыть диалог без изменения состояния приложения
7. WHILE изображение не загружено в Document, THE Frontend SHALL отображать кнопку «Сохранить» в неактивном (disabled) состоянии

### Requirement 8: Компоновка интерфейса (Layout)

**User Story:** As a пользователь, I want to видеть удобно организованный интерфейс, so that я могу эффективно работать с изображением и фильтрами.

#### Acceptance Criteria

1. THE Frontend SHALL использовать layout с тремя зонами: toolbar (верхняя панель фиксированной высоты), canvas (центральная область), sidebar (правая панель параметров шириной от 200 до 320 пикселей)
2. THE Frontend SHALL размещать кнопки «Открыть файл» и «Сохранить» в toolbar
3. THE Frontend SHALL размещать Preview_Canvas в центральной области, которая занимает всё пространство окна за вычетом toolbar и sidebar
4. THE Frontend SHALL размещать список фильтров и их параметры в sidebar
5. WHILE изображение не загружено, THE Frontend SHALL отображать в центральной области приглашение «Перетащите файл или нажмите Открыть»
6. THE Frontend SHALL поддерживать минимальный размер окна 800×600 пикселей, при котором все три зоны остаются видимыми и функциональными
7. WHILE содержимое sidebar превышает видимую высоту, THE Frontend SHALL отображать вертикальную прокрутку внутри sidebar без влияния на toolbar и canvas

### Requirement 9: Backend-команда загрузки изображения

**User Story:** As a Frontend, I want to вызвать Tauri-команду для загрузки изображения из файла, so that пиксельные данные будут доступны в Engine для обработки.

#### Acceptance Criteria

1. THE Engine SHALL предоставлять Tauri_IPC команду `load_image` принимающую путь к файлу (строка длиной до 4096 символов) и возвращающую метаданные документа с загруженными пиксельными данными
2. WHEN команда `load_image` вызвана с путём к файлу поддерживаемого формата (PNG, JPEG, WebP), THE Engine SHALL декодировать изображение, преобразовать пиксели в формат RGBA f32 (диапазон 0.0–1.0) и разместить данные в PixelTile-структурах (256×256 пикселей) в TileCache
3. WHEN команда `load_image` успешно выполнена, THE Engine SHALL вернуть метаданные документа: ширина (пиксели), высота (пиксели), количество тайлов (равное ceil(width/256) × ceil(height/256))
4. IF файл не найден по указанному пути, THEN THE Engine SHALL вернуть ошибку типа IoError с описанием причины (файл не найден)
5. IF файл повреждён или его формат не входит в список поддерживаемых (PNG, JPEG, WebP), THEN THE Engine SHALL вернуть ошибку типа IoError с описанием причины (неподдерживаемый формат или ошибка декодирования)
6. IF размер изображения превышает 8192×8192 пикселей по любой из осей, THEN THE Engine SHALL вернуть ошибку типа InvalidState с описанием причины (превышен максимальный размер)

### Requirement 10: Backend-команда рендеринга превью

**User Story:** As a Frontend, I want to получить отрендеренные пиксели для отображения на Canvas, so that пользователь видит результат обработки.

#### Acceptance Criteria

1. THE Engine SHALL предоставлять Tauri_IPC команду `render_preview(doc_id: DocumentId)` возвращающую base64-encoded PNG полного композитного изображения со всеми видимыми слоями и применёнными активными фильтрами
2. WHEN команда `render_preview` вызвана, THE Engine SHALL выполнить композицию всех видимых слоёв документа в порядке bottom-to-top, применив к каждому слою его активные фильтры, и собрать результат в единый RGBA-буфер размером document.width × document.height пикселей
3. THE Engine SHALL возвращать данные в формате base64-encoded PNG (8 бит на канал, RGBA) для передачи через Tauri_IPC
4. WHEN размер изображения превышает 2048×2048 пикселей, THE Engine SHALL вернуть уменьшенную версию, используя ближайший доступный MipLevel пирамиды так, чтобы результат не превышал 2048 пикселей по большей стороне
5. IF документ с указанным doc_id не найден, THEN THE Engine SHALL вернуть ошибку DocumentNotFound
6. IF документ не содержит ни одного видимого слоя с пиксельными данными, THEN THE Engine SHALL вернуть прозрачное PNG размером document.width × document.height (но не более 2048 по большей стороне)

### Requirement 11: Backend-команда экспорта изображения

**User Story:** As a Frontend, I want to вызвать Tauri-команду для сохранения обработанного изображения на диск, so that пользователь получает файл с применёнными фильтрами.

#### Acceptance Criteria

1. THE Engine SHALL предоставлять Tauri_IPC команду `export_image` принимающую идентификатор документа (DocumentId), путь для сохранения (строка до 4096 символов), формат (PNG или JPEG), и необязательный параметр quality (целое число от 1 до 100)
2. WHEN команда `export_image` вызвана, THE Engine SHALL применить все активные фильтры к изображению в его оригинальном разрешении (ширина и высота документа) и закодировать результат в указанный формат
3. WHEN экспорт в формат JPEG и параметр quality не указан, THE Engine SHALL использовать значение quality равное 90
4. IF запись файла не удалась из-за прав доступа или нехватки места на диске, THEN THE Engine SHALL вернуть ошибку типа IoError с текстовым описанием причины сбоя, не изменяя состояние документа
5. IF указан формат отличный от PNG или JPEG, THEN THE Engine SHALL вернуть ошибку InvalidFilterParams с указанием допустимых форматов, не создавая файл на диске
6. IF документ с указанным DocumentId не найден, THEN THE Engine SHALL вернуть ошибку DocumentNotFound
