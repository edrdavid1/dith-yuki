## Как работает дизеринг в Dither Yuki 2

Дизеринг в приложении — это не один алгоритм, а **набор художественных инструментов** для управления цветом и текстурой. Все они теперь работают как **неразрушающие фильтры**, которые можно навесить на любой слой или корректирующий слой. Благодаря тайловой архитектуре фильтр выполняется только для видимых тайлов, а не для всего изображения.

### Два основных семейства дизеринга

1. **Ordered Dithering (упорядоченный)** — накладывает периодический узор (матрицу порогов) на изображение. Даёт характерную «газетную» или «пиксельную» текстуру.  
   *Реализации:* матрицы Байера (2×2, 4×4, 8×8…), кастомная PNG-карта порогов.

2. **Error Diffusion (диффузия ошибки)** — вычисляет разницу между исходным и квантованным цветом и распределяет её по соседним пикселям. Визуально более плавный, но требует больше вычислений.  
   *Реализации:* Floyd–Steinberg, Atkinson, возможно добавление других ядер.

Оба семейства могут работать как с **равномерной квантизацией** по заданному числу уровней на канал, так и с **ограничением заданной палитрой** (ближайший цвет из палитры).

## Параметры фильтра дизеринга

Ниже таблица всех значимых параметров. Именно они будут сохранены в `FilterInstance.params` и отображаться в UI.

| Параметр | Тип | Значения по умолчанию / пример | Описание |
|----------|-----|-------------------------------|----------|
| `mode` | строка | `"ordered"`, `"floyd"`, `"atkinson"`, `"custom_png"` | Выбор алгоритма дизеринга |
| `levels` | целое | 2–256 (обычно 2, 4, 8, 16) | Количество уровней яркости **на канал**. `2` — чисто чёрный/белый, `256` — почти без изменений |
| `threshold_scale` | float | 0.1–4.0 (по умолчанию 1.0) | Масштабирование порога (ordered) или силы ошибки (diffusion). Меньше 1 — слабее эффект, больше 1 — агрессивнее |
| `pixel_size` | целое | 1–32 (по умолчанию 1) | Размер «блока» в пикселях изображения, который обрабатывается как один большой пиксель. `1` — обычный попиксельный дизеринг, `2` — ретро-эффект с квадратами 2×2 |
| `color_mode` | булево | `true` (RGB) / `false` (Grayscale) | Если `false`, изображение сначала превращается в яркостное (luminance), и дизеринг идёт по одному каналу. Если `true` — каждый канал RGB квантуется независимо |
| `palette_id` | целое (nullable) | `null` или ID палитры | Если задано, квантование происходит до ближайшего цвета из указанной палитры (через KD-дерево). Если `null` — равномерное квантование по `levels` |
| `custom_path` | строка | `""` | Только для режима `custom_png`. Путь к PNG-файлу с картой порогов (с проверками безопасности) |
| `kernel` | строка (опционально) | `"floyd"` / `"atkinson"` | Для error diffusion. Можно добавить свои ядра в будущем |

## Влияние ключевых параметров (с примерами)

### `pixel_size` — главный художественный приём
Представьте, что вы уменьшили разрешение изображения, а потом увеличили обратно без сглаживания.  
- `pixel_size = 1` — обычный дизеринг, пиксель за пикселем.  
- `pixel_size = 2` — каждый блок 2×2 заменяется одним цветом, создаётся эффект «пиксель-арта».  
- `pixel_size = 4` и выше — сильно огрубляет картинку, но даёт узнаваемый стиль.  

В старой реализации вы применяли `div_ceil(tile_size / pixel_size)` для уменьшения эффективного разрешения, что позволяло обрабатывать блоки как отдельные «мегапиксели». В новой системе это нужно перенести без изменений.

### `levels` и `threshold_scale`
- При `levels = 2` и `threshold_scale = 1.0` вы получаете классический чёрно-белый дизеринг.  
- Увеличение `levels` (например, 8) даёт больше полутонов, дизеринг становится менее заметным.  
- `threshold_scale` позволяет тонко управлять интенсивностью: `0.5` — лёгкая текстура, `2.0` — жёсткий контрастный узор.

### `palette_id` против `levels`
Если указана палитра, параметр `levels` игнорируется. Квантование идёт до ближайшего цвета палитры в перцептивном пространстве Oklab (с использованием KD-дерева). Это позволяет добиться точного соответствия цветам, например, для имитации печати или ограниченной палитры старых компьютеров.

## Адаптация к тайловой архитектуре

### Ordered Dithering — непрерывность паттерна
В старой реализации вы использовали глобальные координаты через `global_x = tile_coord.global_x + px`. В новой системе у каждого тайла есть `TileCoord { level, x, y }`. Получить глобальную координату просто:  
`global_x = coord.x * TILE_SIZE + x`, где `x` — локальная координата внутри тайла (с учётом HALO).  
Формула `rem_euclid` для сэмплирования матрицы остаётся той же: паттерн будет бесшовно продолжаться на стыках тайлов.

### Error Diffusion — обработка границ тайлов
Чтобы ошибка корректно перетекала между тайлами, необходимо:
1. **Читать соседние Raw-тайлы** для заполнения HALO‑области (2 пикселя) перед применением фильтра. Это даёт возможность распространить ошибку с соседних тайлов на границу текущего.
2. После обработки **сохранять «хвосты» ошибок** на правой и нижней границе тайла в специальный буфер `ErrorResiduals` (ключ: координаты тайла). Когда следующий тайл (справа или снизу) будет обрабатываться, он прочитает эти остатки как начальное смещение для своих граничных пикселей.
3. Эта механика гарантирует **pixel‑perfect стыковку** даже при тяжёлой диффузии.

## Интеграция в граф фильтров

`FilterInstance` для дизеринга будет выглядеть примерно так:
```rust
FilterInstance {
    filter_type: "dither",
    params: json!({
        "mode": "floyd",
        "levels": 16,
        "pixel_size": 2,
        "threshold_scale": 1.2,
        "color_mode": false
    }),
    palette_id: Some(3), // ссылка на палитру в документе
}
```

При выполнении пайплайн:
1. Достаёт Raw‑тайл.
2. Вызывает `apply_filter_to_tile`, которая в зависимости от `mode` запускает `apply_ordered`, `apply_floyd` или `apply_custom_png`.
3. Если задан `palette_id`, загружает KD‑дерево из кеша палитр документа и заменяет этап равномерного квантования поиском ближайшего цвета палитры.
4. Сохраняет `Processed` тайл в кеш.

Для `ordered` режима никаких проблем с параллелизмом нет — все тайлы независимы. Для `error diffusion` параллельное вычисление тайлов одного слоя возможно, только если они не соседствуют по правой/нижней границе. Планировщик может учитывать это при назначении задач, но на первых порах можно обрабатывать последовательно вдоль строк, чтобы гарантировать корректность.
