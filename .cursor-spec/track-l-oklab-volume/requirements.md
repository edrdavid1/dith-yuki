# Requirements: Track L — 3D Oklab palette volume

## Introduction

Формализация [ADDENDUM_release_plan_L_C4.md](../ADDENDUM_release_plan_L_C4.md)
Track L. Color Lab показывает палитру как облако точек в Oklab `(a, L, b)`
внутри статической оболочки sRGB-гамута — «дыры» в палитре видны как пустоты.

Конверсия **только в Rust** (`oklab.rs`). JS-Oklab запрещён: разъедется с
движком (тот же класс, что Track D parity).

Не зависит от A–K. Можно параллельно с чем угодно.

**Non-goal:** подсветка пикселей холста, квантованных в кликнутый цвет —
отдельный будущий трек.

Карта: [RELEASE_TRACKS.md](../RELEASE_TRACKS.md).

## Glossary

- **OklabPointDto**: `{ l, a, b, srgb_hex }` на цвет палитры.
- **Gamut_Mesh**: оффлайн-посчитанная граница sRGB в Oklab, статический asset.
- **Volume_Viewer**: Three.js point cloud + orbit + клик → selection в Color Lab.

## Goals / Non-Goals

| Goals | Non-Goals |
|-------|-----------|
| IPC `get_palette_oklab` из `oklab.rs` | JS/sRGB→Oklab на фронте |
| Point cloud + gamut wireframe | Runtime voxelization гамута каждый кадр |
| Клик синхронизирует swatch selection | Isolate pixels on canvas |
| Тест координат на Game Boy preset | Полный Color Lab redesign |

## Requirements

### Requirement 1: Backend IPC

**User Story:** As the Color Lab UI, I want engine-authoritative Oklab coordinates for a palette.

#### Acceptance Criteria

1. Tauri command `get_palette_oklab(palette_id)` SHALL load the document palette, convert each color with existing `Oklab::from` / `linear_to_oklab` (same path as quantization), and return `Vec<OklabPointDto { l, a, b, srgb_hex }>`.
2. Missing palette SHALL error clearly (same class as other palette commands).
3. Unit test: built-in Game Boy 4 colors (or document palette created from that preset) → Oklab within documented epsilon of a hand-computed / `oklab.rs` reference.

### Requirement 2: Gamut mesh asset

**User Story:** As a user, I want a faint sRGB-gamut shell so empty regions of the palette are readable.

#### Acceptance Criteria

1. A static mesh (JSON or compact binary of vertices/edges) SHALL live in-repo as an asset, generated by a **dev-time** script (not on panel open).
2. Runtime SHALL NOT recompute the gamut hull per frame or per panel open.
3. Script + how to regenerate SHALL be documented in design.md / script header.

### Requirement 3: Frontend viewer

**User Story:** As a user in Color Lab, I want to orbit the palette in 3D and click a point to select that swatch.

#### Acceptance Criteria

1. `PaletteVolumeViewer` (name MAY vary) SHALL render points at `(a, L, b)` with L as the vertical axis unless a short comment justifies a different mapping.
2. Semi-transparent gamut mesh from Req 2 SHALL be visible behind the cloud.
3. Orbit + zoom (mouse). Three.js MAY be added as a dependency (not currently in `package.json`; addendum listed it as allowed).
4. Click on a point SHALL set the same selection as clicking that color in the manual-edit list — **one** selected index in existing Color Lab state, not a second cursor.
5. Viewer is Color Lab chrome; hidden when no palette/draft colors.

### Requirement 4: Non-goals and manual check

**User Story:** As a reviewer, I want canvas isolation left out of this PR.

#### Acceptance Criteria

1. No tile/composite picking of “pixels of this color” in this track.
2. Manual visual: a palette of only dark + only light colors shows a hole in mid-L.
